ContinuousTransitionMessagePassingRules

The ContinuousTransition node and its variational rules. Use it for a linear Gaussian transition y ~ N(A x, W⁻¹) whose matrix A = f(a) and noise precision W are learned along with the states: a state-space model with an unknown transition, a rotation by an unknown angle, a regression with an unknown matrix of coefficients.

ContinuousTransitionMessagePassingRules — Module
ContinuousTransitionMessagePassingRules

The ContinuousTransition node, y ~ N(f(a) x, W⁻¹): a linear Gaussian transition from x to y through a matrix built from the vector a, with the noise precision W, where a and W are learned alongside the states. Its rules are variational, mean-field or structured q(y, x), with average energies, and run under CTVMP, which carries f and which the model must give. A nonlinear f is linearised with ForwardDiff.

For A = reshape(a, n, m), LinearContinuousTransition with LCTVMP(n, m) computes the same variational updates directly, without Jacobians or linearisation.

Examples

julia> result = @call_message_update_rule(
           node = ContinuousTransition, target = :y, algorithm = CTVMP(a -> reshape(a, 1, 1)),
           q = (x = MvNormalMeanCovariance([2.0], [1.0;;]), a = MvNormalMeanCovariance([3.0], [1.0;;]), W = Wishart(2, [0.5;;])),
       );

julia> m, W = mean_precision(getresult(result));

julia> m ≈ [6.0] && W ≈ [1.0;;]
true

See also ContinuousTransition, CTransition.

Where these rules run

ReactiveMP runs these rules on a factor graph, which RxInfer builds from a GraphPPL model. The examples here call the rules directly, as a test does.

This page follows the node from its definition to its rules, an example and its limitations, and ends with the API.

Overview

ContinuousTransition carries an m-dimensional x to an n-dimensional y through the n × m matrix f(a), with Gaussian noise of precision W. The transformation f makes the matrix as free or as structured as the model needs: a -> reshape(a, n, m) learns every entry, while a rotation a -> [cos(a[1]) -sin(a[1]); sin(a[1]) cos(a[1])] learns one angle.

The node is a stochastic node, a density over its variables, and its rules are those of variational message passing. They update the marginals q(a) and q(W) from the states, and the states from them.

Definition

\[p(y \mid x, a, W) = \mathcal{N}\big(y \mid f(a)\, x,\; W^{-1}\big)\]

The output y is normal around the transformed input f(a) x, with covariance W⁻¹.

A nonlinear f is linearised around the mean of q(a): each row of f(a) is taken as linear in a, through its Jacobian, plus an offset that is zero for an f linear through the origin. The docstring of ContinuousTransition gives the expansion and the messages towards a and W in full.

Algorithm

ContinuousTransitionMessagePassingRules.CTVMP — Type
CTVMP(f)

The algorithm of ContinuousTransition, carrying the transformation f that takes the vector a to the matrix A = f(a). The node declares no algorithm of its own, so a model must give this one; its rules are variational.

Arguments

  • f: a function of a vector returning an n × m matrix, differentiable by ForwardDiff. The rules differentiate it at the mean of q(a), and a nonlinear f is linearised there.

Each target has two rules under CTVMP, one per factorisation:

  • the structured q(y, x) q(a) q(W), reading the messages on y and x or the joint q(y, x);
  • the mean field q(y) q(x) q(a) q(W), reading marginals only.

The marginal rule computes the joint q(y, x). The average energy exists in both factorisations, so the Bethe free energy is available. There is no belief propagation rule.

Limitations

  • Variational only. Every rule needs CTVMP, which the model must give, and marginals on a and W, which need initialising.
  • Multivariate normals only on y, x and a: a scalar state is a vector of length one.
  • A nonlinear f is linearised, around the mean of q(a), so its rules and its average energy are approximate; for an f linear in a they are exact.

Reshape without Jacobians

When every entry of A is learned independently as a parameter, use LinearContinuousTransition with LCTVMP(n, m). It represents the same density and computes the same variational updates as ContinuousTransition with CTVMP(a -> reshape(a, n, m)), to floating-point precision. The covariance of a can be fully dense: the entries need not be statistically independent.

The four interfaces are still y, x, a, and W, with dimensions n, m, n*m, and n × n. Julia's column-major ordering applies: a = vec(A). LCTVMP carries only the shape; the factorisation selects mean-field or structured VMP. Both dimensions are explicit because the structured message towards W cannot determine the split of q(y, x) from its inputs.

@call_message_update_rule(
    node = LinearContinuousTransition, target = :y, algorithm = LCTVMP(2, 3),
    q = (x = MvNormalMeanCovariance([1.0, 2.0, 3.0], Matrix(1.0I, 3, 3)),
         a = MvNormalMeanCovariance(vec([1.0 0.0 1.0; 0.0 1.0 1.0]), Matrix(1.0I, 6, 6)),

)

This node supports the same eight messages, joint marginal, and two average energies. Its message towards a uses weighted mean vec(E[W] * E[y*x′]) and precision kron(E[x*x′], E[W]), so it does not read q(a) or need an initial expansion point.

The rules reshape the parameter mean and contract blocks of its covariance directly. They construct no Jacobians, including constant identity or selection matrices. Message and marginal rules declare scratch matrices that the engine reuses per outbound stream; each call overwrites its scratch and returns separately owned parameters. Sharing LCTVMP across nodes therefore is allowed.

Separate scalar state ports

ScalarLinearContinuousTransition, also exported as ScalarCT, represents the same density with n individual scalar y ports and m individual scalar x ports. It accepts LCTVMP(n, m) or the cached SLCTVMP(n, m) and declares [:y..., :x..., :a, :W]. The parameter vector and precision matrix remain multivariate. No Jacobians are evaluated.

Two factorizations are supported:

  • q(y)q(x)q(a)q(W): each state group retains its full covariance.
  • q(y,x)q(a)q(W): the joint retains covariance across both state groups as well, in [y; x] order.

MeanField() would split every scalar port independently and is not supported for groups larger than one; use the explicit group constraints below.

Incoming state messages must be univariate Gaussians. Outgoing scalar messages eliminate the other coordinates with a Schur complement, including their incoming messages and excluding the target's own message. They are not obtained by taking the diagonal of a block message. With independent incoming state messages, the full local joint agrees with LinearContinuousTransition supplied with the corresponding diagonal incoming covariances. Separate scalar ports cannot represent arbitrary correlations in incoming block messages.

Marginal targets are (:y,), (:x,), and (:y, :x), with all incoming messages in their respective groups. Messages to a and W and the average energy take either the full joint clusters = ((:y, :x) => qyx,) or separate groups clusters = ((:y,) => qy, (:x,) => qx). The message towards a requires no q(a).

The engine's scalar representation of a singleton group is accepted too. An outgoing singleton port may omit its own message group entirely. Other missing messages, partial groupings, and independent scalar marginals for larger groups are rejected. Wrong counts raise DimensionMismatch during rule execution, before working buffers are used.

Caching computations across ports

Use SLCTVMP(n, m; T = Float64) to allocate shared working matrices at algorithm construction. The same instance serves all rules of one node, for either supported factorization. T fixes the floating-point precision of the cache; use T = Float32 for Float32 inference. Inputs are converted to that working precision for cached computations.

One algorithm instance per node

Do not share an SLCTVMP instance between nodes. Their rules would write into the same cache. Each node needs a freshly constructed instance, and calls using that instance must run serially. Inside a model loop, construct SLCTVMP(n, m) in each node's where { algorithm = ... } declaration; do not pass one shared instance to every node.

cached_algorithm = SLCTVMP(2, 3) # Allocate once for this node, reuse across its updates.
@call_message_update_rule(
    node = ScalarCT, target = (:y, 1), algorithm = cached_algorithm,
    m = (y = (nothing, incoming_y), x = incoming_x), q = scalar_parameters,
)

The algorithm snapshots the parameters of q(a) and reuses its moments, the transition precision, and completed Gaussian solves across scalar ports. It compares numerical values on each call, so modifying an existing distribution's arrays also invalidates the relevant cache. Changing incoming weighted means alone reuses the solve; changing a contributing precision rebuilds it. The first sweep may require additional solves as messages arrive. During asynchronous inference, precision changes between ports can reduce the benefit.

Every outgoing scalar message still excludes its own incoming message. The cached solve includes a temporary or previously seen prior on the excluded coordinate; that contribution cancels in the Schur complement. Both factorizations produce the same messages, group marginals, and energies as ScalarCT with LCTVMP, to floating-point precision.

Moment and residual buffers are also reused for parameter and energy updates. Returned distributions own their arrays and remain valid after later calls. The cache trades retained per-node memory for less repeated work; it does not remove output allocations, all input moment allocations, or rule-dispatch costs. LCTVMP remains available as an immutable, shareable configuration with independent scratch per rule stream.

The indexed left-hand side creates separate scalar output variables attached to one factor:

using RxInfer, ContinuousTransitionMessagePassingRules, LinearAlgebra

@model function scalar_transition_example(z, n, m)
    local x
    for j in 1:m
        x[j] ~ NormalMeanVariance(0.5, 1.0)
    end
    a ~ MvNormalMeanCovariance(ones(n * m), Matrix{Float64}(I, n * m, n * m))
    W ~ Wishart(n + 2, Matrix{Float64}(I, n, n))

    y[1:n] ~ ScalarLinearContinuousTransition(x = x, a = a, W = W) where {
        algorithm = SLCTVMP(n, m) # A fresh cache for this factor node.
    }
    for i in 1:n
        z[i] ~ NormalMeanVariance(y[i], 0.1)
    end
end

structured = @constraints begin
    q(y, x, a, W) = q(y, x)q(a)q(W)
end
separate = @constraints begin
    q(y, x, a, W) = q(y)q(x)q(a)q(W)
end

n, m = 2, 3
init = @initialization begin
    q(a) = MvNormalMeanCovariance(ones(n * m), Matrix{Float64}(I, n * m, n * m))
    q(W) = Wishart(n + 2, Matrix{Float64}(I, n, n))
end
result = infer(
    model = scalar_transition_example(n = n, m = m), data = (z = [1.0, 0.5],),
    constraints = structured, initialization = init, iterations = 10, free_energy = true,
)

Both factorizations are tested against the block rules through direct rule calls. The example above runs the full joint factorization. With the installed ReactiveMP 7.0.0, changing it to constraints = separate stalled without producing all requested posteriors or free-energy values, including in probes with explicit initial local marginals. Separate-group end-to-end inference therefore remains an integration limitation; the implementation does not modify RxInfer or ReactiveMP scheduling.

With LCTVMP, each scalar rule repeats an elimination using its own reusable working matrices. SLCTVMP shares computations across the ports of one node; use the benchmarks to compare workloads for your dimensions. The scalar interface connects state components independently while retaining local group covariance.

A convolution as one node

Conv2dContinuousTransition, also exported as Conv2dCT, is a whole two-dimensional convolution with scalar ports: every output position p has y[:, p] ~ N(A * patch(x, p), W⁻¹) with the same A = reshape(a, C_out, kh * kw * C_in) and the same C_out × C_out precision W. Its interfaces are [:y..., :x..., :a, :W], as for ScalarCT, and its algorithm Conv2dVMP carries the geometry and a cache:

conv = Conv2dVMP((4, 4, 1), 2, (3, 3)) # a 4 × 4 image, 1 → 2 channels, a 3 × 3 kernel
(conv.outsize, conv.ny, conv.nx, conv.n, conv.m, conv.bandwidth)
((2, 2, 2), 8, 16, 2, 9, 10)

The image and the output are flat, in column-major order: x = vec(image) and y = vec(output) with the output H_out × W_out × C_out. The model never indexes rows and columns; conv.taps[j, p] holds the index in x of entry j of the patch at position p (0 for zero padding), a patch being vec of its kh × kw × C_in window. stride and pad are keywords, each an integer or a (rows, columns) pair.

The same rules as CTVMP

The node is the linear Gaussian transition whose matrix repeats the kernel at every position. With B(a) that ny × nx matrix, it is ContinuousTransition under CTVMP(a -> B(a)) with W repeated for every position, kron(W, I), and independent state messages, that is, messages on y and x with diagonal covariances:

  • the joint q(y, x), and q(y) and q(x) under q(y)q(x), have the same means, variances and entropy;
  • the message towards a scalar port is that posterior's marginal without the port's own incoming message;
  • the message towards a is the same, since the kernel is CTVMP's own a;
  • the message towards W is WishartFast(C_out + 1 + positions, R), with R the sum over positions of the diagonal blocks of CTVMP's residual;
  • the average energy is the same.

The tests check every one of these against CTVMP on convolutions with strides, padding and several channels. What differs is the cost: CTVMP differentiates B(a) and works with dense ny × nx and (ny + nx)² matrices, where this node never forms either.

Latent images: a banded system

With a latent image the outputs of every position are eliminated in closed form, which leaves a system over x alone that couples two pixels only when a patch contains both. x is ordered with the channels of a pixel together and then along the shorter side of the image, so that system is banded, with bandwidth conv.bandwidth, about C_in * ((kw - 1) * H + kh). A banded Cholesky factorisation and a selected inverse (the Takahashi recursion) give every mean, every variance and every covariance inside a patch, which is all the node needs, in O(nx b²) time and O(nx b) memory. A 28 × 28 image with a 3 × 3 kernel is 1,460 ports with bandwidth 58: its joint takes 2.4 ms and 0.2 MB, where a dense solve would factorise a 1,460 × 1,460 matrix. The precision of a port's message is formed as a Schur complement over the port's own row, never as 1 / variance minus its incoming precision.

Given q(x), as for an observed image, the positions are independent and only a C_out × C_out system per position is solved.

In an inference engine: ports

An engine asks for the message towards every port in a call of its own. ports says what that call receives:

portsfactorisationa port's message is read from
:jointq(y,x)q(a)q(W)the joint q(y, x)
:separateq(y)q(x)q(a)q(W), latent xq(y) or q(x)
:observedq(y)q(a)q(W), x given as dataq(y); no message goes to x
:defaultany of thesethe other messages of its group, as the engine's default scheme delivers them

With :joint, :separate and :observed the node solves once per iteration, when the group's marginal is computed, and every port reads its message from the result, in constant time. :observed also keeps the moments of the observed patches in q(y), so the rules towards a and W never read the pixels again. :default works under every factorisation and for direct calls: each port's rule receives the other messages of its group, and one solve is reused across ports while the inputs stay the same. Prefer the other three for large images. Create one Conv2dVMP per node.

@model function conv2d_batch(x, z, insize, cout, kernel, batch, noise)
    local y
    template = Conv2dVMP(insize, cout, kernel)
    ny, nx, d = template.ny, template.nx, template.n * template.m
    a ~ MvNormalMeanCovariance(zeros(d), Matrix(10.0I, d, d))
    W ~ Wishart(cout + 2, Matrix(1.0I, cout, cout))
    for b in 1:batch
        ys, xs = ((b - 1) * ny + 1):(b * ny), ((b - 1) * nx + 1):(b * nx)
        y[ys] ~ Conv2dCT(x = x[xs], a = a, W = W) where {
            algorithm = Conv2dVMP(insize, cout, kernel; ports = :observed) # A fresh cache for every image.
        }
    end
    for i in 1:(batch * ny)
        z[i] ~ NormalMeanVariance(y[i], noise)
    end
end

with constraints = @constraints begin q(y, a, W) = q(y)q(a)q(W) end, and x and z the concatenated vecs of the images and of their noisy convolutions. This is integration/conv2d_mnist.jl, which learns a kernel from a batch of MNIST images and has its own environment, because RxInfer is not a dependency of this package:

For a latent image, give every pixel its own prior, keep y and x together with q(y, x, a, W) = q(y, x)q(a)q(W), and use ports = :joint.

The reference of a port's message is CTVMP's whole message towards y, which an engine computes once for all of y; the node's row is the read of one port, after the joint. The reference of q(y) is CTVMP's mean-field message towards y times the incoming messages.

API

The node and its alias.

ContinuousTransitionMessagePassingRules.ContinuousTransition — Type
ContinuousTransition

The stochastic node of a linear Gaussian transition whose matrix is itself learned:

\[p(y \mid x, a, W) = \mathcal{N}\big(y \mid A x,\; W^{-1}\big), \qquad A = f(a),\]

taking an m-dimensional x to an n-dimensional y through the n × m matrix f(a). The transformation f is carried by the node's algorithm, CTVMP, which the model must give. CTransition is an alias.

Interfaces

  • y: the output, an n-dimensional vector;
  • x: the input, an m-dimensional vector;
  • a: the parameters of the matrix, always a vector, of length one for a single parameter;
  • W: the n × n precision of the transition noise.

Rules

Every rule is variational and runs under CTVMP, in one of two factorisations:

  • structured, q(y, x) q(a) q(W): messages towards y and x from the messages on x and y (MvNormal), messages towards a and W and the average energy from the joint q(y, x) (MvNormal), and the marginal rule for q(y, x);
  • mean-field, q(y) q(x) q(a) q(W): every message and the average energy from the marginals.

q(a) must have a mean and a covariance, q(W) a mean and, for the average energy, the expectation of logdet, as a Wishart has. The rule towards a also reads q(a), its expansion point, besides the inputs its factorisation gives it, so q(a) needs an initial marginal.

Linearisation

The rules treat each row of A as linear in a. With Fᵢ the Jacobian of the i-th row of f at the mean mₐ of q(a), and Ā the matrix they use for f(mₐ),

\[A(a) \approx O + \begin{bmatrix} (F_1 a)^\top \\ \vdots \\ (F_n a)^\top \end{bmatrix}, \qquad O = \bar{A} - \begin{bmatrix} (F_1 m_a)^\top \\ \vdots \\ (F_n m_a)^\top \end{bmatrix}.\]

Ā is f linearised at mₐ + σₐ, the mean plus one standard deviation of q(a) per component, and evaluated at mₐ, which is f(mₐ) exactly for a linear f. The offset O is zero for an f linear through the origin, such as reshape, and the rules towards a and W and the average energy keep it for any other f, such as a rotation. The expectation of AᵀWA then has the closed form ĀᵀW̄Ā + Σᵢⱼ W̄ᵢⱼ Fᵢ Σₐ Fⱼᵀ, W̄ being the mean of q(W) and Σₐ the covariance of q(a), which every rule uses.

The message towards a is a normal with weighted mean and precision

\[\xi = \sum_i F_i^\top \, \mathbb{E}\big[x (y - O x)^\top\big] \, \bar{W}_{:, i}, \qquad \Lambda = \sum_i F_i^\top \, \mathbb{E}[x x^\top] \sum_j \bar{W}_{j i} F_j,\]

and the message towards W is a Wishart with n + 2 degrees of freedom and the inverse scale E[(y - A x)(y - A x)ᵀ].

Limitations

  • Variational only: under the default algorithm, DefaultAlgorithm, no rule exists, and a model that does not name CTVMP finds none.
  • Multivariate normal messages and marginals on y, x and a only.
  • A nonlinear f is linearised as above, so its rules are approximate.

ContinuousTransitionMessagePassingRules.LinearContinuousTransition — Type
LinearContinuousTransition

The stochastic node y ~ N(A * x, W⁻¹) with A = reshape(a, n, m). Its interfaces are [:y, :x, :a, :W]: an n-vector output, an m-vector input, the n*m-vector of matrix entries, and the n × n noise precision. Julia's column-major ordering applies: a = vec(A).

Supply LCTVMP(n, m) to specify the shape. Its rules are the exact reshape case of ContinuousTransition with CTVMP(a -> reshape(a, n, m)), computed without Jacobians or linearisation. They support mean-field q(y)q(x)q(a)q(W) and structured q(y, x)q(a)q(W): messages towards all four interfaces, the joint marginal q(y, x), and both average energies. Gaussian solves and contractions of the full covariance of a are still required.

The distribution families are the same as for ContinuousTransition. The message towards a does not read q(a) or require an initial expansion point; other messages still need q(a). There are no rules under DefaultAlgorithm() or for belief propagation.

ContinuousTransitionMessagePassingRules.LCTVMP — Type
LCTVMP(n, m)

Shape configuration for LinearContinuousTransition: A = reshape(a, n, m) maps an m-vector to an n-vector. Both dimensions must be positive integers. The algorithm stores only these dimensions, not a transformation function or Jacobians; the factorisation selects ordinary mean-field or structured VMP.

Message and marginal rules declare scratch matrices that the inference engine allocates once per outbound stream and reuses. Scratch is separate from the algorithm and from returned message parameters, so sharing this immutable configuration does not share mutable buffers. Direct calls allocate fresh scratch unless the caller supplies it through the rule execution API. Average energies do not retain scratch between calls.

Explicit dimensions are needed in particular for the structured message towards W, whose inputs q(y, x) and q(a) do not determine which dimension belongs to y.

ContinuousTransitionMessagePassingRules.ScalarLinearContinuousTransition — Type
ScalarLinearContinuousTransition

The density y ~ N(reshape(a, n, m) * x, W⁻¹) with separate scalar state ports. Its interfaces are [:y..., :x..., :a, :W]: n scalar outputs, m scalar inputs, the n*m-vector a = vec(A), and the n × n noise precision. Supply LCTVMP(n, m) or SLCTVMP(n, m) to cache computations across this node's scalar ports.

Supports q(y)q(x)q(a)q(W) and q(y,x)q(a)q(W), with full covariance inside each state group. Incoming state messages are univariate Gaussians; group marginals are multivariate Gaussians in interface order, [y; x] for the full joint. Separate scalar messages cannot encode arbitrary correlated multivariate incoming messages.

Address scalar ports with target = (:y, k) or (:x, k). Pass message tuples with nothing at the excluded target, and group marginals through clusters. Wrong group sizes raise DimensionMismatch during rule execution. Singleton groups may use the engine's one-element tuple of scalar marginals instead of a joint marginal.

Rules use covariance contractions and Gaussian elimination without Jacobians. Under LCTVMP, the engine reuses scratch per stream. Under SLCTVMP, the algorithm owns a cache and must not be shared between nodes or concurrent calls. Returned parameters own their arrays.

ContinuousTransitionMessagePassingRules.SLCTVMP — Type
SLCTVMP(n, m; T = Float64)

Cached algorithm for ScalarCT, with n scalar outputs and m scalar inputs. Supports both q(y)q(x)q(a)q(W) and q(y,x)q(a)q(W), with the same rules and Gaussian messages as LCTVMP, up to floating-point roundoff. Positive integer dimensions allocate the cache immediately; T <: AbstractFloat fixes its working precision.

Create a separate instance for every node. Sharing an instance between nodes is not allowed: their rules would write into the same cache. Calls using one instance must also run serially, not concurrently. In a model loop, construct SLCTVMP(n, m) inside each node's where { algorithm = ... } declaration. Reuse that instance for successive calls belonging to the same node.

The cache stores parameter snapshots, transition precision, and Gaussian solves for the state groups. It checks parameter values, including in-place edits, before reusing results. Changing only incoming weighted means reuses the solve; changing precisions invalidates it. Each outgoing scalar message still excludes its own incoming message exactly. Shared moment buffers serve parameter and energy updates; returned distributions own their arrays.

This trades retained per-node memory for fewer repeated computations across scalar ports. It does not eliminate allocations for returned distributions, input moment extraction, or rule dispatch.

ContinuousTransitionMessagePassingRules.Conv2dContinuousTransition — Type
Conv2dContinuousTransition

A whole two-dimensional convolution as one stochastic node with scalar state ports: y[:, p] ~ N(A * patch(x, p), W⁻¹) independently for every output position p, with the same A = reshape(a, C_out, kh * kw * C_in) and the same C_out × C_out noise precision W at every position. Its interfaces are [:y..., :x..., :a, :W].

The image and the output are passed as flat groups of scalars in Julia's column-major order: x = vec(image) for an H × W × C_in image and y = vec(output) for the H_out × W_out × C_out output. A patch is ordered as vec of its kh × kw × C_in window, so a = vec(A) with one row of A per output channel. Conv2dVMP carries this geometry; the model only indexes x[1:length(image)] and y[1:length(output)].

Supports q(y)q(x)q(a)q(W) and q(y,x)q(a)q(W), as ScalarCT does, and also independent scalar marginals for a whole state group, such as the PointMass marginals of observed pixels. Incoming state messages are univariate Gaussians. The node is the exact linear Gaussian transition whose matrix repeats the kernel: its rules agree with ContinuousTransition under CTVMP(a -> the convolution matrix of a) given independent (diagonal) state messages, and overlapping patches are handled inside the node rather than by loops between nodes. Group marginals are Conv2dMarginals.

ContinuousTransitionMessagePassingRules.Conv2dVMP — Type
Conv2dVMP((H, W, C_in), C_out, (kh, kw); stride = 1, pad = 0, T = Float64, ports = :default)

Cached algorithm for Conv2dCT: the geometry of the convolution and the working memory of one node. stride and pad are integers or (rows, columns) pairs; padding is with zeros. The output has H_out = (H + 2pad - kh) ÷ stride + 1 rows, likewise for columns, and C_out channels.

The fields ny, nx, n = C_out, m = kh * kw * C_in, positions = H_out * W_out, outsize and taps describe the layout: taps[j, p] is the index in x of entry j of the patch at position p, or 0 for padding, and channel c of position p is y[p + (c - 1) * positions].

ports says what the message towards a state port is computed from, and with it how the node behaves in an inference engine:

  • :default: the engine's default scheme, under any supported factorisation. Every port's rule receives all the other messages of its group, and one solve is reused across ports while the inputs stay the same.
  • :joint, for q(y,x)q(a)q(W): every port reads its message from the joint marginal, which is computed once per iteration. One rule serves all ports.
  • :separate, for q(y)q(x)q(a)q(W) with latent x: likewise from q(y) and q(x).
  • :observed, for q(y)q(a)q(W) with x given as data: likewise from q(y), which also carries the moments of the observed patches, so no other rule reads the pixels again. No message is sent towards x.

Create a separate instance for every node, inside its where { algorithm = ... } declaration, as for SLCTVMP: rules of one instance write into the same cache and must run serially.

Latent inputs are solved exactly in a banded system over x: the outputs of every position are eliminated in closed form, x is ordered so that a patch spans a narrow band, and a banded Cholesky factorisation with a selected inverse gives every mean, variance and patch covariance in O(nx b²) time and O(nx b) memory for bandwidth b, the field bandwidth, about C_in * ((kw - 1) * H + kh). That memory is allocated on first use.

ContinuousTransitionMessagePassingRules.Conv2dMarginal — Type
Conv2dMarginal{T}

The marginal of a state group of Conv2dCT: q(y, x), q(x) given q(y), or q(y) given q(x). The joint covariance is never formed. It holds what the node's other rules and the free energy read:

  • mean and var: of every member, [y; x] for the joint;
  • ξ and λ: the weighted mean and precision of the message towards every member, which excludes that member's own incoming message;
  • Exx, Eyx, Eyy: the second moments E[x x'], E[y x'], E[y y'] of the patches, summed over positions, with complete saying whether all three are held;
  • entropy: the differential entropy, also returned by entropy(q).

members is :yx, :x or :y, and ny the number of y members it starts with.
